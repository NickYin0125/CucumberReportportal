## Publication Gates

Previous GitHub CI failed before tests because its fresh runner had not registered
the upstream Helm repository. Shared validation now registers that repository,
builds the locked dependency, checks deployment profiles and runs offline tests.
Tag publication reuses that validation and verifies stable tag/version agreement
and main-branch ancestry before publishing verified assets and checksums.

The PR, main and tag runs must finish successfully before publication is called
complete. GitHub Release publication is not RubyGems/private-registry publication.
No Huawei production deployment, HA certification, historical migration,
exactly-once delivery or zero-loss guarantee is included.

## First Cloud Attempt

The first PR and branch runs reached the full suite and exposed four failures on
Ubuntu/Ruby 3.3: two runtime-specific backtrace assertions, a GC lifetime check,
and a genuine JSON-parser encoding mutation in Multipart validation. Publication
was blocked. A standalone Ruby 3.3.12 container reproduced the Multipart failure;
parsing a duplicate prevents mutation of the binary JSON source. The fixed probe
and 17 focused Multipart checks pass. Subsequent run results remain the required
publication gate; the earlier local 847/0 results are not relabeled as cloud success.

The compatibility follow-up passed **848 examples, 0 failures, 0 pending** in the
manager's Ruby 3.4.2 integrated repeat, plus the default Cucumber profile. The 6.1
Sol reviewer ran the three affected lifecycle/GC specs: **19/19** on Ruby 3.4.2
and containerized Ruby 3.3.12. The manager separately ran both Multipart specs in
that Ruby 3.3 container: **17/17**. GC isolation retains the two actual thread-local
mirrors and proves item retention before mirror replacement and release afterward;
production context behavior is unchanged. Cloud validation is still mandatory.

The corrected PR, branch, main and tag validation all passed. Tag run
`38406093937` also built and preserved original artifact `11817114228` for commit
`71b63023fbf9318147a175c3e637fdd87195b82e`, but publication stopped after creating
an empty draft: the by-tag API hid that draft behind a 404. The authenticated
