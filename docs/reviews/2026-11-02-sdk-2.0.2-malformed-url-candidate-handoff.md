## 1. Credential-Redaction Defect

### Root cause

`EvidenceRedactor#redact_plain_text` tokenizes URLs with `%r{(?:https?:)?//[^\s"'<>]+}`. In `https://example.test/bad path#%7B%22pass%5Cu0077ord%22%3A%22…%22%7D` the URL token ends at the space. The remainder `path#…` went to `redact_plain_segment`, which matches only literal key names and never percent-decodes, so the encoded `password` key was invisible. Direct `redact_url` on the whole string masked it because its fragment path decodes encoded JSON. The defect is pre-existing and independent of policy reuse: fresh and shared policies produced identical leaking output.

### Candidate fix (`9b1ec873`, `lib/reportportal_cucumber/automation/evidence_redactor.rb`)

1. `redact_plain_text_segment`: after the unchanged literal pass, each whitespace-delimited token containing `%XX` goes through the existing URL query/fragment helpers (`redact_fragment_query`, `redact_fragment`). The original frame now renders `https://example.test/bad path#%7B%22password%22%3A%22%5BREDACTED%5D%22%7D`, identical to direct `redact_url`.
2. `encoded_credential_split?`: if an encoded token's sensitive key has its value in the next whitespace token, the text is withheld (OMITTED). This reuses the existing `credential_crosses_units?` scanner on percent-decoded adjacent tokens.
3. `cross_unit_credential?`: also checks percent-decoded units, so an encoded key ending the message or one frame, with its value in the next frame, takes the existing whole-failure boundary path (`fallback_only: true`, OMITTED baseline).
4. `encoded_credential_exposed?`: a post-condition that percent-decodes the output (up to 3 passes) plus JSON `\uXXXX` and fails closed if any sensitive key still has a non-mask value.

All four paths are skipped for text without a `%XX` escape, which therefore takes the byte-identical previous path. Nothing is cached; no per-call state is shared.

### Follow-up: direct `redact_url` route (`b449a433`)

While preparing this handoff, a separate pre-existing gap was confirmed. `redact_url` decoded fragments and query values, but passed path segments and valueless query parts (`?%7B…%7D`) through literal matching only. `https://example.test/%7B%22password%22%3A%22S%22%7D` was returned unchanged. That method backs HTTP evidence (`http_exchange.rb:34`, `evidence_presenter.rb:392`), not only failure text.

- `redact_url_path` and `redact_encoded_component` apply the existing encoded-fragment rules per path segment and per valueless query part, including in `fallback_redact_url`. Components whose decoded text has no `:`, `=` or `bearer` are left unchanged, so `/users/%7Bid%7D/profile` stays readable.
- `redact_url` now fails closed (OMITTED) when its decoded output still shows an unmasked credential (same post-condition as the text route).
- New `spec/reportportal_cucumber/automation/evidence_redactor_encoded_url_spec.rb` (28 examples): `password`, `password` and `api_key` in path segments, last segment, valueless query (alone and between pairs), path plus fragment; encoded `key=value` path segments; double encoding; the malformed-URL fallback; five safe URLs byte-identical; idempotence; `HttpExchange` summary and plain/rich Markdown; and the `EvidencePresenter.failure` card. On `9b1ec873` these give **28 examples, 23 failures** (all leak and caller cases; the 5 safe controls pass). On `b449a433`, 0 failures.
- One earlier test (`failure_redactor_malformed_url_spec.rb`) expected OMITTED for credential JSON in a well-formed URL path; it now asserts the exact masked URL instead.
- The original probe still exits 0 on `b449a433` (`security-probe/url-fix-*`).

## 4. Remaining Risks And Unexecuted Criteria

- `b449a433` widens the change from failure text to HTTP evidence URLs; reviewers should check it as a behaviour change for those callers (masked path segments and query parts, or OMITTED URLs).
- Split-credential cases withhold the whole text or failure, so safe frames are lost in those rare cases (fail-closed by design).
- Possible over-masking: encoded tokens decoding to brace-led non-JSON (for example `#%7Bfoo%7D`) become `[REDACTED]`, matching existing URL-fragment policy; decoded text resembling `token:12` withholds the text.
- Not covered: encodings beyond three percent layers, HTML entities, base64 and other escape schemes.
- G11 performance remains **NOT RUN** for `50b` and the candidate. A quiet host and container window is required; the percent-escape path needs a separately labelled supplementary measurement.
- An independent container rerun of the probe, Ruby 3.3, and CI are outstanding.
- P1.6, P10.8, P10.10, P10.11 and named F18 coverage remain **pending**; nothing was run against live RP.
- QA-workspace additions (`focused_window3.rb`, the `QA202-9b1ec87-20261102/` evidence) are **uncommitted** on `qa/presentation-ledger-2.0.2`, alongside the existing uncommitted QA evidence, which was not modified.
