## Performance And Preserved Failures

The independent comparison used frozen baseline `3f20313`, the same pinned
arm64 Ruby 3.4.12 container, Cucumber 12.0.1, dependency bytes, one CPU and
2 GiB memory. Both complete frozen21 rounds passed: full failure processing
p95 3.525-3.604 ms, 39%-45% below baseline. F07 median overhead was 1.09% plain
and 1.18% rich. Presentation p95 maxima were 0.997/0.985 ms, below 2 ms.

The initial busy-environment preflight remains NOT RUN. The first isolated
window retains its complete frozen21 results and an F07 harness-packaging
failure; two missing unchanged fixture files were restored, and seven untimed
validity checks passed before a separately authorized remaining-only window.
No passing round was selected from retries and no threshold was relaxed.
The report discloses both windows and diagnostic host load. RP and Typewords
were temporarily paused with owner permission and automatic restoration;
their combined pause duration was about 427 seconds. Both resumed successfully.

## Promotion Boundary And Limits

Release preparation after the tested SHA changes documentation and its packaging
specifications only. Promotion must prove all runtime, non-Markdown example,
dependency, workflow and release-tool bytes unchanged, then pass full CI at
the metadata head. Live results must continue to name the actually executed
SHA; later documentation or merge commits are linked by explicit byte identity,
not described as new live executions.

Merge PR #8 into `codex/cucumber-12` only after these checks. The immutable tag
pipeline separately verifies ancestry, package identities and checksums before
publishing the Gem, unchanged Helm 1.3.1, checksums and provenance. This report
does not itself claim that future tag publication has already completed.

R02 remains unresolved by owner choice: Hide All Passed Logs can hide evidence
owned by a passed After Hook. The example uses one RP screenshot entry and does
not duplicate that PNG into native Cucumber HTML. Native F16c remains N/A;
its separate adapter probe is not a claim that Ruby can raise a non-Exception.
Raw caller AppLog messages are not globally sanitized. Benchmarks are local
offline measurements, not production-throughput or universal-security guarantees.
No RubyGems publication, 1.x change, main-line migration or deployment is included.
