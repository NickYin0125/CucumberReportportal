# M2: actionable diagnostics and caller-owned evidence

Status: implementation contract. M1's `SUITE -> STEP(hasStats=true) -> STEP(hasStats=false)` topology and existing `rp_log`/`rp_attach` remain unchanged. M2 does not depend on Playwright or manage screenshots, recording, retention, transcoding, or video playback.

## Public contract

| Method | Behavior |
| --- | --- |
| `rp_capture_target` | Returns an opaque, immutable handle for the currently open Gherkin step, manual step, or hook. Returns `nil` outside an open action. A handle identifies one item in one scenario attempt. |
| `rp_evidence(action:, error:, url: nil, details: nil, artifacts: [], target: nil)` | Reports one concise `ERROR` summary plus optional bounded diagnostics and caller-supplied artifacts. `target: nil` means the currently open action, never an implicit Scenario/Launch fallback. Returns `true` when queued, `false` when disabled, invalid, or already closed. A rejected call warns locally and must not retarget to a hook or retry. |
| `AppLog.assertion(name:, expected:, actual:, passed:, details: nil, report: true)` | Emits a concise terminal status and a redacted, bounded Markdown comparison to Cucumber and RP through the existing logger routing. It records a diagnostic; it does not change Cucumber's pass/fail result or raise an assertion. |

An artifact is a hash with `path:` or `bytes:`, plus optional `name:` and `mime:`. The caller chooses what to capture. A path-backed artifact remains a path through RP queuing and multipart upload; do not load a large file merely to format a preview. In-memory bytes must have an explicit size ceiling and a clear rejection outcome. The client infers a safe filename and MIME when omitted, without silently relabeling bytes as video. Existing `rp_attach` behavior remains compatible.

The summary contains action, sanitized URL when provided, exception class/message, and a short indication of available evidence. `details` and structured expected/actual values get a capped Markdown preview. All *text generated by these new APIs* is sanitized before terminal, Cucumber, RP, and spool routes. Binary evidence is opt-in and cannot be promised sanitized. No call may replace the original Playwright or test exception; caller code re-raises it after reporting if desired.

## Implementation slices

1. **Target lifecycle.** Extend `Runtime::Context` with a lock-protected open-target registry. Register a target when a Gherkin step, hook, or manual step starts. On close, stop accepting new writes, drain accepted writers up to the configured deadline, flush buffered logs, then finish the item; cancel tardy publications rather than allowing them after finish. A target includes launch/item/attempt identity internally but exposes no UUID arguments to testers. Validate explicit targets against the current runtime, launch, and open registry. Retry attempts receive distinct handles.
2. **Failure evidence route.** Add `World#rp_capture_target` and `World#rp_evidence`, with formatter methods that enqueue a summary, diagnostic text, and each artifact against the validated target UUID. Take a bounded delivery barrier before finishing the target item. Preserve failed-action attribution even when a later hook is active. Reject late or foreign handles without raising from failure-reporting code.
3. **Presentation and privacy.** Add a pure formatter for the failure summary and assertion comparison. Reuse `EvidenceRedactor` for text before it reaches any output route. Keep terminal lines brief; attach full-but-bounded Markdown only to report tracks. Do not put raw secrets in spool metadata or fallback diagnostics.
4. **Consumer example and docs.** Show a Playwright 1.62 missing-locator example in which the framework/tester catches the original error, optionally produces a screenshot and console excerpt, calls `rp_evidence`, and re-raises. No automatic browser inspection, video capture, or Playwright runtime dependency.

## Acceptance cases

| ID | Scenario | Observable result |
| --- | --- | --- |
| M2-01 | Missing-locator error plus caller-supplied screenshot and console excerpt | One `ERROR` summary and evidence logs have the failed Gherkin step UUID, not the Scenario or After-hook UUID; original exception remains the test failure. |
| M2-02 | No artifact supplied | Readable error summary still appears, with no fabricated attachment. |
| M2-03 | Scenario retry or next Step after capture | Each attempt has a distinct handle; explicit late write to a closed handle returns `false` and never moves to the next action. |
| M2-04 | Failing Before/After hook and manual `rp_step` | Evidence binds to the active hook/manual step; finish order is log flush before item finish. |
| M2-05 | Two concurrent scenarios | Handles and emitted item UUIDs remain isolated. |
| M2-06 | Capture/reporting error while test is failing | Reporting warns and degrades; the original test error is not replaced. |
| M2-07 | Large path-backed file and oversized in-memory bytes | Path is streamed without full read; bytes over the documented ceiling are rejected; bounded previews do not exceed limits. |
| M2-08 | Sensitive URL, structured details and assertion values | Credentials are absent from terminal, Cucumber, RP request body, and spool text; binary artifacts are explicitly caller-owned. |
| M2-09 | Assertion pass and fail | Markdown shows expected versus actual and outcome; terminal stays concise; diagnostic does not alter Cucumber status. |
| M2-10 | Compatibility and regression | Existing M1 tests, full `bundle exec rspec`, and ordinary `bundle exec cucumber` pass; no Playwright dependency is added. |
