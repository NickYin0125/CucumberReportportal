## Design Risks And Testable Assertions

1. **Guard before content work.** The 64 KiB input budget must be enforced before transcoding, scanning, cloning full oversized text, or whole JSON parsing. Oversized input yields a fixed fail-closed marker; parser nesting errors, invalid encodings, cyclic containers, and unknown object types must not lead to raw fallback. Clarify per-field versus aggregate accounting across structure keys and values; bounded output is not itself bounded input work.
2. **Sanitize before any clip.** Decode complete in-budget JSON keys before classifying them. Embedded JSON in ordinary error text, ambiguous/malformed JSON-like text, Unicode escape errors, and excessive nesting must fail closed rather than expose an encoded sensitive key. A parser-success check alone does not cover embedded structures. Preserve readable ordinary small safe text.
3. **URL syntax before presentation limits.** Strip complete in-budget userinfo even with `@` beyond 512 bytes, then clip. Decode credential query names before classification; malformed percent escapes must not restore raw sensitive values. Do not infer URL safety merely from output length or an absent terminator in a sliced prefix.
4. **Structured classification before bounds.** Determine Hash sensitivity using complete bounded keys before shortening keys or values. A normalized-sensitive key with a long separator prefix and escaped JSON inside a Hash value are adversarial cases. Retain summary <=512 bytes, details/Markdown <=16 KiB, value <=4 KiB, 256 nodes, depth 8, valid output encoding, and unchanged input. Unknown objects and serialization exceptions must never echo their unsanitized `to_s`.
5. **Shared credential policy.** F3 requires normalized-exact matching for existing defaults and agreed common aliases, across case and separators, regardless of custom allowlisting. Avoid substring matching that blocks safe business keys such as `token_count`. Reject unsafe configuration with generic errors containing no values. Policy and standalone attributes/redactor require paths must not depend on Cucumber.
6. **Only nil means current.** F4 must reject explicit false with zero evidence enqueue on a later Step and an After hook. Closed, foreign, and arbitrary capabilities remain rejected; nil and valid original open capabilities retain their documented behavior. Review acquire/publish/release invariants and explicit-capability thread behavior without redesigning context ownership. Preserve `SUITE(hasStats=true) -> Scenario STEP(hasStats=true) -> actions/hooks(hasStats=false)`.
7. **Sink closure is separate from presenter correctness.** Public evidence and assertion paths must carry safe text through formatter/native/terminal/API/spool boundaries. Transport error strings are also untrusted diagnostics. Inspect ordinary and fallback spool metadata, not just record messages. Raw binary attachments are explicitly unsanitized opt-in artifacts; legacy logger paths are not silently recertified as universal sanitizers.
