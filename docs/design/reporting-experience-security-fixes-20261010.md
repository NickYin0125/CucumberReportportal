## Design And Acceptance

| Finding | Design | Required acceptance evidence |
| --- | --- | --- |
| F1: diagnostic clipping destroys credential syntax | Sanitize complete bounded input before clipping any failure/assertion field; decode JSON keys before classification. Ambiguous encoded JSON, invalid URLs, unsupported diagnostic objects, and inputs over 64 KiB fail closed with a fixed omission marker. Never serialize an unsafe object as a rescue fallback. | Original escaped-key JSON and long-userinfo reproductions fail on the baseline and pass on the candidate. Verify summary <=512 bytes, details <=16 KiB, structural values <=4 KiB, depth/node budgets, valid UTF-8, unchanged caller inputs, and preserved safe small diagnostics. |
| F1: downstream persistence | Keep generated diagnostic text safe through terminal, native Cucumber World, real formatter/queue/API, and natural transport-failure spool paths. Sanitize bounded spool exception metadata too. | Canary-free JSON/multipart metadata, ordinary NDJSON spool, fallback spool, and warnings under synthetic transport failures; original browser/test exception remains primary. Opted-in raw attachment bytes are explicitly outside this guarantee. |
| F3: credential aliases in custom allowlists | Share a dependency-light normalized-exact credential-key policy. Custom allowlists cannot override it; case and separator variants are rejected. Preserve safe business keys and configuration precedence. | Reject credential aliases through both the helper and public Config, with generic errors containing no submitted values. Retain default seven-key behavior, safe custom keys, precedence, and disabled behavior. |
| F4: false capture sentinel retargets | Only `nil` means implicit current target. All explicit values must pass the existing capability registry; do not alter acquire/publish/release ownership or add Scenario/Launch fallback. | `false`, arbitrary, closed, and foreign handles enqueue nothing in a later Step/After hook. Nil-current and valid original/cross-thread open capabilities still work. |

The sanitization budget favors confidentiality over a partial preview: input
too large to classify safely is omitted, rather than preserving a possibly
credential-bearing prefix. This is not universal PII detection or automatic
sanitization of legacy logs, screenshots, file bytes, or videos.
Automatic Step/manual-step exception and backtrace logs, and native Cucumber
core failure payloads, retain their original behavior. Publishing safe evidence
does not sanitize a separately re-raised browser exception. Reporting warnings
and spool exception metadata are included in this patch; opted-in raw attachment
bytes are not.

Secondary review must also close newly reproduced same-scope edges: incomplete
embedded escaped keys/delimiters, mixed percent-encoded fragment syntax,
encoded JSON fragments, and intra-word credential-key separators. Artifact
metadata generated by `rp_evidence` must obey the same bounded policy without
rewriting raw bytes or changing legacy `rp_attach`. Structural traversal counts
must include rejected Hash keys, and valid tiny output limits must bound omission
markers as well as normal text. These are F1 safety hardening, not new milestones.

The official reporting topology remains unchanged:
Feature `SUITE(hasStats=true)` -> Scenario `STEP(hasStats=true)` ->
actions/hooks `hasStats=false`. Identity, attributes precedence, links,
statistics, lifecycle ordering, and queue retry/flush behavior are not
redesigned by this patch.
